# 9. Component Identification and Characterization Sheet

| Component | Purpose | Library / class | Key parameters | Measured runtime | Measured memory | Alternatives considered |
|---|---|---|---|---|---|---|
| Stream source + drift injector | Produce window t's features and hidden labels under a chosen scenario | `telltale.data.stream.generate_stream`, `telltale.data.injector` (pure numpy) | T=150, N=2000, d=20, base fraud rate 2 percent | About 4.7s to generate one full 150-window stream | Negligible (a few arrays of 150x2000x20 floats, about 24 MB) | A real transaction pool (used instead for the P1 Kaggle check); rejected as primary because it has too little natural drift and too few frauds to calibrate against |
| Deployed model | Score each window's transactions | `sklearn.ensemble.HistGradientBoostingClassifier` | `max_iter=60`, no class weighting (see Section 1.4) | About 0.3 to 2s per fit on 40,000 rows (20 training windows x 2000) | Not separately profiled; small relative to the data arrays | `class_weight="balanced"` (rejected: measured 6 to 10s fixed overhead per fit on this machine, regardless of data size); logistic regression (P1 item, not reached) |
| Input drift monitor | Per-feature PSI and KS against the reference | `telltale.monitors.input_drift` (numpy, `scipy.stats.ks_2samp` for KS) | 10 quantile bins, top-5-of-20-features aggregation | Included in the 5.6 ms/window combined monitor figure below (KS is computed only on demand for diagnostics, not every window) | Included below | Maximum Mean Discrepancy (Gretton et al., 2012): rejected for this project mainly on cost and interpretability grounds (a kernel two-sample test is heavier at this window size and does not decompose into a per-feature explanation the way PSI does) |
| Score / confidence monitor | PSI on log-odds scores, alert-rate ratio, mean entropy | `telltale.monitors.score_drift` | Alert budget 2 percent (operating threshold fixed at calibration time) | Included below | Included below | ATC-style accuracy prediction (Garg et al., 2022): closest prior art, folded in as the alert-ratio and entropy signals rather than adopted as a separate full method |
| Calibrator | Convert raw statistics to a common evidence scale via a resampled null | `telltale.monitors.calibration` | 300 bootstrap draws, 99th-percentile threshold, whole-window-then-within-window resampling (see Section 1.4) | About 0.4 to 0.7s per reference rebuild (vectorised; an earlier unvectorised version measured about 135s) | Not separately profiled | A parametric null (assume a known distribution for each statistic) was rejected in favour of resampling, since PSI and the alert-ratio statistic do not have a convenient closed-form null distribution at this bin count and window size |
| Evidence combiner | Merge input and score evidence, run CUSUM | `telltale.monitors.combiner`, `telltale.monitors.cusum` | Combined CUSUM: slack 1.0, height 1.0 (tuned); backstop CUSUM: slack 2.2, height 1.0 | All 8 strategies' monitor + policy overhead on one scenario/seed averages well under a second beyond model-fit time | Negligible | An adaptive window (ADWIN, Bifet and Gavalda, 2007) was considered and used as a desk-study comparison point (Section 8) rather than adopted, since it needs a labeled error signal in its common form |
| Backstop | Watch matured-window recall, CUSUM on sustained drops | `telltale.monitors.backstop` | Recall at 2 percent alert budget, z-scored against the 10 calibration windows | Negligible beyond the recall computation itself (`telltale.metrics.recall_at_budget`, an argpartition over each window) | Negligible | DDM-style error-rate tracking (Gama et al., 2004) is the direct ancestor; adapted here to only ever see matured, delayed labels instead of an immediate error signal |
| Retrainer | Refit on the W most recent matured windows, rebuild the reference | `telltale.models.Retrainer` | W=20 windows, 5-fold blocked out-of-fold scoring when a monitor reference is needed | About 15.5s when a reference is needed (6 fits), about 2.8s when it is not (1 fit) | Not separately profiled | Online/incremental updating of the existing model (instead of a full refit) was not implemented; full refit on a sliding window matches PRD 6.6 exactly and keeps every strategy comparable |
| Monitor (combined, operational) | Per-window evidence computation at serving time | `telltale.monitors.combiner.compute_window_evidence` | N=2000 (default window size) | 5.6 ms/window at N=2000 (profiling); scales from 8.5 ms at N=1000 up to about 1.5s at N=1,000,000 | 80 KB peak at N=2000, up to about 39 MB at N=1,000,000 | N/A, this is the project's own component |

Full scale-up numbers (window size from 1,000 to 1,000,000 transactions) are in
`results/profiling.json` and plotted in `results/figures/scale_up_runtime.png`.
