# 12. Initial Qualitative Risk List

| # | Risk | Likelihood | Impact | Mitigation | Evidence |
|---|---|---|---|---|---|
| 1 | Label-free signals cannot see pure concept drift | High (by construction) | High: silent failure on exactly the drift type that looks like nothing changed | The delayed-label backstop exists for exactly this case; S4 is a dedicated scenario to measure it honestly rather than hide it | Pilot and tuning-seed runs: label-free monitor stayed silent on S4 in 4 of 5 tuning seeds (the one alarm matches the calibrated false-alarm rate); backstop detected it within D + a few windows |
| 2 | Seasonality mistaken for drift | Medium | Medium: alert fatigue, lost trust in the system | Null calibration is built from the reference period's own variability, including any seasonality already present there (S6); whole-window bootstrap resampling preserves the within-window structure a naive row-level bootstrap would wash out | Found and fixed during Phase 3 tuning: an early, row-level bootstrap gave S6 roughly 3x the target false alarm rate before the fix (docs/dev_log.md) |
| 3 | Thresholds calibrated on a short reference window are noisy | Medium | Medium: either too many false alarms or a threshold too loose to detect real drift | 10 calibration windows is the PRD's fixed design; the null is built with 300 bootstrap draws per signal, and resampling within each chosen window (not just between windows) widens the estimated tail instead of capping it at 10 discrete outcomes | A dedicated null-calibration test (`tests/test_null_calibration.py`) checks a fresh window's exceedance rate directly, not just the bootstrap's own self-consistency |
| 4 | Retraining on contaminated or adversarially shaped data | Low in this simulation, real in production | High if it happens | Out of scope for this project's threat model, but the retrain window (W=20 matured windows) limits how much any single contaminated window can dominate a retrain | Not tested; flagged as a limitation (report Section 14.4) |
| 5 | Feedback loop: the model's own decisions change which cases get labelled | Medium in production, not modelled here | Medium to high: biases future training data toward what was already flagged | Not modelled; the simulation's hidden labels are generated independently of the model's predictions | Explicit limitation, PRD Section 2.2 |
| 6 | Gap between the simulation and real fraud data | High (any simulation) | Medium: results may not transfer directly | The P1 semi-synthetic check on the Kaggle credit card dataset exists specifically to see whether detection behaviour holds outside the synthetic generator; Section 14.4 states clearly what does and does not transfer | Run only if `data/raw/creditcard.csv` is available; logged in dev_log if skipped |
| 7 | Label delay that varies case to case rather than being fixed | Medium in production | Medium: a fixed D is a simplification | PRD's sensitivity sweep (P1) varies D across 0, 3, 7, 14 to show how exposure and detection delay scale with it, which at least characterises sensitivity even though it does not model a variable per-case delay | Sensitivity results if run (P1 item) |
| 8 | Alert fatigue from false alarms | Medium | High: analysts start ignoring the system | The false-alarm target (PRD 6.5, H5) is tuned and tested directly on S0 and S6 before the main run even happens | `results/tuning.json`, `results/summary.json`'s false_alarms block |
| 9 | PSI is sensitive to binning and sample size | Medium | Low to medium: noisy input-drift signal | Fixed 10 quantile bins from the reference, computed once per reference and reused (not recomputed per window), with the top-5-of-20-features aggregation smoothing out single-feature binning noise | `telltale/monitors/stats.py`'s PSI unit tests (near-zero for identical distributions, grows with shift) |
| 10 | High-dimensional drift hidden by averaging over features | Medium | Medium: a drift confined to one or two features could be diluted by the top-5 mean | Mitigated partly by taking the mean of the top 5 (not all 20) PSI values, so only the most-shifted features count; not a complete fix for drift in a single feature among many | Not stress-tested beyond the 4-feature covariate shift the generator implements |
| 11 | Overfitting thresholds to the simulation | Medium | Medium: tuned parameters might not generalise | Tuning uses only the 5 tuning seeds (100-104); evaluation uses 10 entirely separate seeds (0-9) that the tuning never saw, with a safety margin (0.5 per 100 target instead of PRD's 1 per 100 ceiling) built in for exactly this risk | `results/summary.json`'s false-alarm rate on the evaluation seeds, compared against the tuning-seed rate in `results/tuning.json` |
| 12 | Information leakage inside the simulation | High impact if present, actively tested against | High: would invalidate every result | `telltale/data/label_vault.py`'s `LeakageError`, raised if any code requests a window's labels before `now - window >= D`; covered by `tests/test_label_vault.py` and exercised by every simulation run, not just a unit test in isolation | All 38 project tests pass, including the leakage guard |
| 13 | Retrain after an alarm uses too few post-drift labels | Medium | Medium: a retrain right at the maturity boundary may still be mostly pre-drift data | The deferred-retrain wait (D + m, m=3 by default) exists specifically to ensure at least m post-alarm windows have matured before retraining | `tests/test_policy_timing.py` confirms the timing rule holds |
| 14 | Anonymised features in public data limit explanations | Medium (applies to the Kaggle P1 check) | Low to medium: harder to narrate which features drove an alarm in the real-data check | Acknowledged directly in Section 5.4's scope note; the synthetic generator's named features do not have this problem | N/A for the synthetic main experiment |
| 15 | Compute cost grows with the number of monitored models | Medium in a real deployment with many models | Medium: operational cost at scale | The scale-up note (Section 14.5) extrapolates measured per-window monitor time and per-retrain time to estimate the cost of monitoring many models at once | `telltale.cli profile` output |
| 16 | Project delivery risk: single developer, one-night deadline | Realised | High: directly limits scope | Addressed with PRD's own cut list: evaluation seeds cut from 20 to 10 (confirmed with the author), P1 items (sensitivity sweeps, second model, real-data check, interim adaptation) attempted only if time remains after all P0 work | `docs/decisions.md`, `docs/dev_log.md` document every cut and why |
